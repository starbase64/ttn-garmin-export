TTN Garmin Export · User guide

A local, independent tool for reading Garmin Connect data. It does not edit activities or settings. Not a Garmin product.

Windows starter · TTN Garmin Export

Extract the complete ZIP to a writable folder and double-click Start-TTN-Garmin-Export.cmd. The first launch downloads private Python and pinned dependencies from official sources, verifying checksums. No admin rights or existing Python required. Missing packages are repaired on subsequent starts. Setup requires Internet; later offline exports do not. Check the console and setup.log for setup errors. The internal GarminExportStudio profile name is retained for existing sessions.

0.4 · Faster health downloads and Downloads folder

Default output: your account's actual Downloads folder, including redirected Windows locations, with a Garmin_Export subfolder. Choose another location at any time. Existing downloads are not moved automatically: reuse the previous output directory and archive, or import the old cache from the Data page.

Full measurement timelines (default): full daily summaries now batch up to 28 consecutive missing days per call while preserving their existing daily request identities and all returned summary fields. Other detailed timelines such as heart rate, sleep and stress remain daily; Body Battery and activities retain their existing batching. Speedup depends on selected datasets.

Daily statistics (faster): choose Export → Output → Health data. Heart rate, sleep, stress, Body Battery, steps, floors, intensity minutes, respiration, hydration and resting heart rate use daily statistics instead of timelines. Category labels change accordingly. Other categories, including HRV, SpO2 and activities, remain unchanged. Available statistics vary by endpoint; no timelines are invented. Choose Wide layout for one row per statistics record or Long layout for one row per leaf value.

Batch size: Options → Health: days per range query, 1–28 (default 28). Size 1 or disabled batching still retrieves the chosen data type one day at a time. Request pacing and rate-limit stops remain. Preview samples only a few days within its query budget. Reload field paths and adjust previous detail filters after changing the detail level if needed.

Offline and resuming: statistics use separate -daily dataset names in cache, exports and SQLite, never overwriting full details or satisfying a detailed-timeline request. Select the matching detail level for offline export; missing data yields OfflineDataMissing without network access. Download / update selected datasets honors the chosen detail level. Download / update all supported data always retains full measurement timelines.

Missing dates in range responses are queried individually with the matching daily endpoint, never silently marked empty. Unsupported or unexpected ranges fall back to the same data type per day. Rate/auth/connection blocks stop the run. Monitoring FIT files and full Garmin account-archive import are not new download routes in this version. Live Garmin calls and Windows execution remain unverified here.

0.3 · Optimized retrieval and estimated time remaining

Batch supported date ranges is enabled by default. Body Battery batches up to seven missing days; activity lists use paginated date ranges of 31 days by default, configurable from 1–365. Detailed heart rate, sleep, stress and many other daily endpoints remain daily without reducing resolution. Speedup varies by dataset; default request pacing is unchanged.

Existing daily cache/SQLite entries are checked before planning. Only contiguous missing or explicitly refreshed days are batched, retaining old daily request identities. Reuse the same account, output/cache directory and archive file; do not delete existing data. Refresh recent days still applies (0 reuses existing recent days too). Unsupported or malformed range responses fall back to daily retrieval; missing Body Battery response dates are individually queried, not silently marked empty. Only Body Battery and activity lists treat successful empty ranges as empty. Missing daily summaries/statistics are checked individually. Rate/auth/connection blocks stop rather than triggering an aggressive fallback.

Download / update selected datasets on Offline data uses the categories chosen on Export. Sport/field filters do not restrict this raw archive download; filter later during local export. The original all-supported-data button remains. Details/files are only included when activities are selected.

Estimated time remaining uses measured task durations by data type/files/cache and includes request pacing. Initially it shows Calculating. Provisional means additional activity/file workload is not yet known. New work, slow files or server variability can increase the estimate; this is not a guaranteed finish time. Retry waits show a countdown, rate limits stop the estimate and show the request pause with no automatic restart. Manual resumption replans remaining work. Output writing is a separate phase; offline exports do not show a fictitious Garmin download ETA. The request counter counts app library read calls, which may internally entail additional HTTP calls; logical daily progress is distinct.

The small Windows update overlays the existing portable app folder, preserving runtime. Stop the old operation, wait for output writing and close before replacing files. Reuse account/cache/archive paths to resume existing work. No Python reinstall or dependency upgrade is needed. Real Garmin range retrieval and Windows execution still require validation.

New: Data browser, maps and summaries · 0.2

Getting started: On Data, open a SQLite archive and select Load data. Create/populate an archive under Offline data first, or import activity files. No login is required for local viewing. “Export source” in the header controls the separate general export/preview buttons. Import existing export cache reads a matching account-…/cache-v1 folder locally, including previous raw responses. CSV summaries are not full archives.

Filters and selection: Filter by date, exact stored sport type, search text (name/location/description) and minimum distance. Save/load named local filters including hidden/reordered columns. Click headers to sort, drag to reorder, use Columns to show/hide. Click selects one row; Ctrl+click toggles rows; Shift+click selects a contiguous range in current order. Checkboxes use the same selection. Select all filtered selects all matching rows. Filter changes clear selection; language changes preserve it.

Map: Recorded GPS tracks appear to the right with colors and legend. Tracks are read locally on demand in a background thread; Stop cancels between files. Missing GPS is explicitly indicated. Wheel zooms, drag pans, Fit includes all selected tracks. Drag the divider to resize. Small windows scroll; large track displays are simplified without changing originals.

Offline / online: Without online map, tracks render on a coordinate grid without street tiles. Online map (OSM) explicitly enables internet access for currently visible OpenStreetMap tiles, with a local cache, even when export source is offline. No offline area download is offered. The map provider necessarily sees requests for the displayed area. Toggle online map off/on to retry failed tiles.

Google Maps: The optional Google Maps window displays selected recorded tracks or the frequency heatmap using your own enabled Maps JavaScript API key. Google billing, referrer restrictions and terms apply. No key is bundled or persisted; the temporary browser page loads Google content. Key/billing restrictions or WebEngine/graphics configuration can prevent display. This view has not been live-tested with a real key here.

Heatmap and recurring routes: Each selected activity votes once per visited cell, avoiding sample-rate/pause weighting. Colors are relative to the current selection. This is approximate trip frequency, not time spent or a medical interpretation. Recurring routes uses approximate geographic grid overlap (~250 m at equator, 85% overlap); similar but different routes may be grouped.

Sharing: Save a native map PNG with Tour image or recorded tracks with Share KML. Open Google My Maps, create a map, import KML and generate a sharing link there manually. No automatic upload occurs. KML does not transfer a rendered heatmap. Hide start/end masks a radius in meters around both endpoints in the map, PNG and KML; table metrics still describe full activities.

Daily data: One stored date per row. Supported values include steps, sleep duration/score, resting heart rate, nightly HRV, average stress, maximum Body Battery, average weight and calories when present in supported responses. Missing values remain blank. No medical interpretation or artificial second-by-second interpolation. Additional raw fields remain available in general export. Date filters apply; sport/search filters affect activities only.

Summaries: Month/year tables group activity count, distance, duration and ascent by sport for the currently filtered activities. Unknown values remain blank; partially available values sum only known readings. Compare displays 2–20 selected activity summaries side by side. Selection, daily and aggregate tables support CSV/XLSX/JSON. The general export page retains other original/detail formats.

New: Import, repair and backup

Import multiple FIT/GPX/TCX or ZIP files, including nested activity archives from an official Garmin export. ZIP paths are never extracted. Supported activity files are imported; other account JSON and wellness FIT do not become daily health rows. An activity date is required. FIT multisport sessions are summarized together. GPX/TCX retain supplied timezones; missing timezone information cannot be inferred.

Original files and summaries are stored in SQLite. Duplicate matching uses start, sport and rounded distance/duration; different timezones/metrics may leave duplicates. Imported daily lists are marked as partial local imports during offline export. They never stand in for a complete fetched Garmin day. Sign in to the matching Garmin account before creating an import archive if you want to sync it online later. New unsigned import archives use a local identity and are not automatically linked to a subsequently signed-in account.

Limits: 128 MiB per supported file, 1 GiB outer ZIP, four nested levels and 30,000 ZIP members. Failed/unsupported files are counted in the report. For larger Garmin exports, extract/select the required activity files first. Stop preserves completed imports.

Fill missing data offers GPX for selected Garmin activities lacking readable tracks, retry failed requests, or missing selected daily categories within the general Export date range. It requires the matching account, skips local import IDs and honors request pauses without automatic restart. Stored responses can still contain measurement gaps.

Create backup uses SQLite backup and validates the copy. Reopen a saved copy with Open file, without Garmin login. Check database verifies format/schema and SQLite integrity, not complete coverage of all Garmin data. Version 0.1 archives remain supported.

New: Session log and oldest activity date

A timestamped UTF-8 log is appended per app start under the local user profile logs folder. Open log opens it; Export current session log saves a copy. A session remains whole across midnight or multiple starts in one day. Display clearing and its 500-line limit do not truncate the file. Credentials, tokens and raw server responses are excluded. JSON/export/archive reports remain separate. Logs are not automatically deleted; remove old files manually if desired.

The optional Suggest first activity as start date checkbox performs at most two extra activity API calls after sign-in, using the oldest remaining activity date only when the start date has not been intentionally set. Health records may precede that activity. Optional lookup failures do not undo login; rate limits activate the local pause.

Preview before exporting

After signing in, configure your export and click “Show preview” at the bottom. A separate window shows up to ten example rows per table by default, using the same columns, units, sport and field filters as the export. JSON shows a bounded sample of the original structure. A full export may include additional columns or values.

Options includes “Preview: rows per table” (1–50, default 10) and “Preview: maximum queries” (1–50, default 12). Activities are sampled from at most three small result pages within the configured range. Other daily categories sample at most the first three days. The entire date range is never scanned. Garmin may still return a complete response for a single day. The query limit bounds application read calls; internal library retries may cause additional network requests.

An empty sample does not prove the entire date range is empty. When many categories are selected, the query budget may run out before every category is sampled; the window indicates this. Table display is limited to the first 100 columns and 4,000 characters per cell. JSON lists and large objects are visibly truncated. Extra details are sampled for the first matching activity only. GPX/FIT and other original files are not downloaded. Expert queries are not executed in the preview.

The preview stays in memory without creating export or cache files. Stop takes effect between queries. Close the preview to adjust settings, reload it or start the actual export. Preview is optional and never starts an export automatically.

Offline data: download once, export later

The optional “Offline data” page manages a self-contained SQLite file. Normal online use does not require creating a database.

Initial download: Sign in to Garmin, choose From/Through dates on Export (including multiple years), choose an existing or new database filename, then click “Download / update all supported data”. All 27 standard datasets are requested regardless of export checkboxes and sport filters. Devices, records and active goals are current snapshots rather than historical series. The sport taxonomy is included. Arbitrary expert queries and other Garmin features such as nutrition are outside this bulk operation.

Optionally include activity details (Garmin-resolution timelines, laps, splits, heart-rate zones, exercise sets and weather) and original files. Details and ORIGINAL are enabled by default. GPX, TCX, KML and Garmin’s lap CSV can also be selected. Only successfully saved formats are available offline; no FIT-to-GPX conversion is implemented. Large initial downloads need many requests and can take a long time. Options supports 1–8 parallel requests (default 3). One shared interval separates request starts (default 0.5 seconds, at least 0.25 seconds for archive sync). Transient network/server failures use the configured retries; archive sync uses at least one retry. HTTP 400/403/429 is never retried. Rate limits and connection failures stop the run while preserving saved responses. A feature rejected with HTTP 400/405/422 is skipped for the rest of that run while unrelated datasets continue.

Resume / update: Use the same file with the same account and desired dates. Existing responses are reused; new days and gaps are added. “Refresh recent days” controls which recent days are fetched again. 0 reuses all existing daily responses; missing ones are still fetched online. Current account snapshots are refreshed on each sync. Successful empty responses are stored. A later failed refresh never deletes a successful older response. Existing successful JSON/file-cache responses can be imported without retrieving them again.

Inspect stored data: Shows saved and missing days, responses, empty responses and unresolved errors for the chosen range. A stored response may contain only metadata, so saved days do not guarantee complete measurement timelines. Per-activity details and files are grouped in the overview. Failed attempts and sync reports are stored inside the database.

Offline export: Choose the file and enable “Use offline data only for previews and exports”. No Garmin sign-in is required. Configure dates, datasets and formats on Export; previews and exports now read only SQLite, even during a local Garmin request pause. Sport types and field paths can also be loaded locally. Missing data is reported as OfflineDataMissing, with no automatic online fallback. Previews use a bounded sample of stored records. Expert offline exports are not supported yet.

The archive is self-contained; after a running operation finishes it can be backed up or copied to another computer as a single file. It contains health data, device metadata and optionally GPS/original files, but no saved login tokens or passwords. There is no additional encryption. Do not publish private database files to GitHub; common SQLite extensions are in .gitignore. “All supported data” is not a promise of a complete Garmin account backup.

Daily raw data as FIT file: Optionally save an unchanged wellness ZIP per day. Select it on Export and use “Download selected data”. The standard full sync does not add it. No CSV/Excel conversion or table preview is available yet. Selecting this does not automatically replace JSON datasets; selecting both still makes additional requests. Availability depends on account and device.

1 · Sign in

On Account, enter email and password. If required, a dialog asks for your two-factor code. Enable China only for garmin.cn accounts. Passwords are not saved to disk. However, “Remember session” saves an authentication token without additional encryption in your user profile. After successful sign-in, the app also remembers your email and China-account setting and restores the session automatically on the next start. The password is never saved. Sign in once with this option enabled after updating; older versions did not save this startup selection. Rejected tokens disable automatic restore while keeping the account and China setting filled in. A log hint replaces repeated startup dialogs. Transient network/server failures keep automatic restore for the next start. An active request pause prevents automatic restore. Someone with access to it may be able to use your account. Do not enable this on shared computers. “Remove local session” deletes the saved session of the currently signed-in account and signs you out of this application. Without signing in, it removes the session for the entered email and China setting. Turning “Remember session” off disables automatic sign-in; use Remove to delete stored tokens.

Without session persistence, sign in again after closing the app. The Garmin library connects to Garmin services. No uploads to the author and no telemetry. A real login and export still need testing with your account.

2 · Dates and datasets

Both dates are inclusive. Multiple years are supported. Every selected daily category is requested for every day. Start with two days and a few categories. Account snapshots represent current state and are not filtered by the historical date range. Sleep follows Garmin’s day assignment, commonly the wake-up date; shift work and overnight sleep may differ.

Categories include daily summary, heart rate, sleep, stress, Body Battery, steps, floors, intensity minutes, respiration, SpO₂, HRV, resting heart rate, weight, body composition, blood pressure, hydration, training status/readiness, VO₂max, fitness age, endurance score, hill score, activities, devices, records and goals. Calories are included in daily summaries. Each category preserves available fields and timelines. Availability depends on the account and device; the tool does not guarantee all account data or old detailed samples.

3 · Activities

Simple list like Garmin Connect: On Export click “Activity list only (CSV)”, select dates, choose a sport on Options and start the export. The shortcut selects only the activity overview and CSV, enables one table row per activity, disables extra downloads and combines the range without year splitting. Existing dates and sport selection remain unchanged. 30 matching activities produce 30 data rows.

Columns: date, start time, name, sport, location (when provided), distance in km, duration hh:mm:ss, average speed km/h, ascent/descent, average power, heart rate, calories, ID and Garmin link. Missing data stays blank. Headers follow the selected language; German semicolon/tab CSV uses decimal commas. Excel retains numeric cell types. Names/locations describe the tour; download GPX separately for the complete GPS track.

This readable activity table is independent of the generic long/wide layout. Disable “Activities: one table row per activity” for generic tables of all API fields. Field filters also work for the standard summary columns. JSON preserves the original fields of matching activities. The raw cache contains all retrieved activities for the day before local sport filtering.

Subtypes such as E-mountain bike are filtered locally by Garmin type key. Parent sports include descendants when the Garmin type hierarchy is available. Without it, exact matching is used and a warning is logged. Daily lists are retrieved without a server-side sport filter, with explicit pagination.

Select Activities – summary to enable additional laps, splits, zones, weather, exercise sets and metric timelines. Choose the sport from a searchable dropdown. After successful sign-in the app loads Garmin’s full activity type list; “Refresh list” reloads it. “All sport types” disables the filter. The list includes sports without any of your own activities. Labels follow the selected language; the Garmin key in parentheses remains unchanged. New or unknown types are shown with their keys. If retrieval fails, a default selection remains available. Custom Garmin keys can still be typed. Original downloads: ORIGINAL (usually ZIP containing FIT), GPX, TCX, KML and Garmin activity CSV. Some formats may not exist for some activities. Field filters do not alter original files. “CSV (laps)” under Original downloads retrieves Garmin’s per-activity split export. For the simple list, leave this off and select CSV on the Export tab.

4 · Formats and resolution

JSON: full responses, preserving native nesting, types and timestamps. Field filters apply only to CSV/Excel, never to JSON or the local raw cache. If you intend to share only selected fields, share only the filtered tables.

CSV / Excel, long layout: one row per leaf value, with source_date, dataset, path, value and type. Timelines, empty objects, empty lists and null remain identifiable. /heartRateValues/0/0 means the first value of the first pair. Timestamps are separate leaf rows; matching array indices preserve their relationship with samples. Different sample intervals are not artificially merged.

Wide layout: one row per top-level record. Nested dictionaries become columns; nested lists remain JSON inside cells. Convenient for summaries; use long layout or JSON for detailed timelines. These generic detail tables do not invent second-level resolution or convert units/time zones, or calculate extra weekly/monthly aggregates.

CSV uses UTF-8 with BOM, with semicolon, comma or tab as separator. Numbers retain their original decimal point; use Excel’s Text/CSV import as needed. Formula-like text is prefixed with an apostrophe in tables; JSON is unchanged. Excel rows spill to additional sheets at the row limit. Unrepresentable cell values cause an export error instead of silent truncation; use CSV/JSON in that case.

5 · Individual fields

“Load fields” retrieves the first selected category for the start date and lists its field paths. Select paths and apply them. Blank means all fields. Enter one path pattern per line: /totalSteps selects one field, /sleepDTO a subtree, /heartRateValues/*/* all value pairs. * matches one path segment. Filters apply to every selected category; use separate runs for different category filters. API field names remain stable in both languages. In wide layout, arrays occupy one cell: select their parent path instead of array indices.

A preview is a sample from one day and may miss fields available on other days. Filtering affects tables, not retrieval or the raw cache. Select fewer categories if you want to retrieve less data.

6 · Resume and storage

Each account gets a separate identifier below the output folder. The selected SQLite archive holds the shared raw responses for online export and archive sync. cache-v1 holds older raw files; exports holds results and report.json. Cache data is sensitive and can become large. Resume with the same account and output folder. Successful requests are reused; failures are not marked successful, while empty responses are cached. “Refresh recent days” refreshes recent days; 0 means reuse every available cached request. To refresh older data, select the desired date range and increase Refresh recent days to include those dates. Current account snapshots are always refreshed.

By default, exports/current below the account folder is updated in place for the current selection. Keep separate export folders restores separate result folders per output profile. Unrelated manual files are retained; stale files from the previous generated export are removed. Stop takes effect between network calls, so an ongoing call may take a while. Retrieved data is then written out. Please wait during writing. Completed cache files survive crashes.

7 · Expert mode

Choose any public get_* reader exposed by the bundled library, including gear, nutrition, training plans and badges. The signature and original English documentation explain parameters. Not every query works for every account. Custom API paths, write operations and generate_defaults=true are disallowed.

Parameters must be a JSON object, e.g. {"cdate":"{date}"}. {date} is replaced for each day; {start} and {end} represent the entire date range. With “Per day” enabled, the method runs for each day. For range methods such as {"startdate":"{start}","enddate":"{end}"}, disable Per day to avoid repeatedly retrieving the same range. Methods without date parameters return their current state. IDs, required parameters, page sizes and pagination depend on the method; not every method paginates automatically. For example, get_gear_list accepts start and limit: export separate pages explicitly. Expert mode does not support methods returning binary data instead of JSON.

8 · Troubleshooting and publishing

Connection errors: Messages now include the error type, available HTTP status and a recognized category, without showing private response bodies. Successful sign-in does not prove every data endpoint is accessible. HTTP 400 indicates a rejected query; HTTP 403 indicates denied access. Without a status code, the exact cause remains unknown.

Rate limit / TooManyRequests: Stop fetching and signing in repeatedly. The app honors Garmin’s Retry-After header when available, otherwise applying a cautious local 15-minute pause. The pause is saved in the user profile and survives restarts. It does not guarantee Garmin will allow access afterwards. Nothing restarts automatically. After expiry, make at most one manual preview attempt; wait longer if still limited.

Library API retries are disabled for clients created by this app; export retries are controlled by Options. Client errors such as HTTP 400/403/429 are not retried. After a connection failure, export and preview stop rather than querying more days or categories over the failing connection. Individual missing resources can still be logged as errors. Library sign-in strategies may still require multiple technical steps.

Missing data may reflect device capabilities, disabled sensors, sync gaps, retention or Garmin services. null is not a measured zero. Metadata in a response does not prove a complete timeline. Network errors have bounded retries. Authentication failures and rate limits stop the run; retry later. Reports contain exception types, not credentials. completed=true means the run ended without reported errors, not that all requested data exists; always check stats.errors. Raw data, reports and screenshots can contain personal details. Never upload them publicly to GitHub.

The Windows EXE bundles Python and dependencies; users do not need Python installed. Unsigned builds may trigger Windows security prompts. Source, tests and a GitHub build workflow are included. A Windows build and a real Garmin login/export test are required before public release.

First activity date and reset

The first activity date detected by the account lookup is saved per account. The most recently selected start dates on Export and Data are saved separately. First activity on Export and Reset to first activity on Data restore the saved account date without another Garmin request. The end date is not persisted. If the account date is not yet known, a successful login with Suggest first activity enabled detects it once; automatic session restore can also perform this one-time lookup. Later logins reuse the saved value. Reset is disabled until the date is known. A local archive may contain only part of the account history.

One shared account archive

New exports default to account-ID/exports/current. Keep separate export folders instead creates separate results per date range/output profile; changing request interval or worker count alone does not create another profile. Existing older folders are not deleted automatically.

Online exports now use the same selected SQLite archive as offline sync. Successful cache-v1 responses, including older accidentally nested account caches, can be imported without another download. New responses remain available for later exports. The database format is unchanged.

A new result folder does not imply a new download. Online mode still retrieves missing responses and those selected by Refresh recent days; 0 reuses all available day responses. Current account snapshots are refreshed online. Daily statistics and full timelines are different resources. Select offline-only mode to guarantee no Garmin requests.

Current output files are staged before publication. A write failure retains the previous export; exports/last-error.json holds the error report. Earlier result folders are not merged or deleted automatically; the shared raw account archive is the source for new exports.

Experimental: skip likely empty requests

Under Options, off by default. Daily data requires daily summary selected. Only explicit empty measurement fields may skip certain individual requests; missing fields and sport names alone never suffice. This is an inference, not proof of absent detail data. Stored responses take precedence. Previews are unchanged.

Offline data shows “Unverified skipped days”. These days still count as missing and the run is incomplete. Offline exports report missing detail data. “Retrieve skipped requests anyway” fetches marked requests within the From/Through dates using the matching signed-in account, bypassing the optimization, including activity extras. Request pauses and rate limits still apply. Alternatively disable the option and repeat the export. Actual responses replace markers. Savings depend on the account and have not been validated against live Garmin data.
